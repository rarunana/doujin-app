# 同人即売会お買い物アプリ

同人即売会(コミケ・東京流通センター)当日の買い物を、スマホ1台で管理するWebアプリ(PWA)です。
ホーム画面に追加すればアプリのように起動し、一度開けば圏外でも動きます。

## 現在の機能(開発ステップ6まで)

- イベントの作成・切り替え(会場、予算)と、開催日(1日目・2日目…)の切り替え。開催日が1日だけなら日付を表示、2日以上ならリストボックスで切り替え。日の名前を空欄にすると日付だけを表示
- サークルの登録(名前、ペンネーム、ホール・ブロック・番号、優先度、X(Twitter)、メモ)。見出しにサークル名とペンネームを表示
- 頒布物ごとの値段・数量、サークル別の合計
- チェックボックスで購入済みを記録。「⋯」から「売り切れ」「見送り」も選べる(売り切れ・見送りはチェック不可)。頒布物が2つ以上あるサークルはまとめてチェックできる
- サークルの見出しをタップで頒布物リストを開閉(全て閉じる・開くも可)。閉じた状態はその端末に記憶。編集は見出し右上の鉛筆ボタンから
- Xのアカウントを登録すると、見出しに「@アカウント名 ↗」のリンクを表示(開くには通信が必要)
- この日の予定額・購入済み額、イベント全体の予算の残り、購入点数の進み具合
- 「未購入」の絞り込み、配置順(東→西→南)・優先度順の並べ替え。買い終わったサークルは下へ
- 会場図とピン(画面下のタブ「マップ」。「リスト」といつでも行き来できる)。日ごとに会場図の画像を読み込み、サークルのピンを置いて表示
- 島の編集(L1)。会場図の島を囲んで各辺の番号を入れると、配置番号からピンが自動で置かれる
- 会場データ(マス目)。Excelのようなマス目で作った会場の配置を使うと、配置番号からピンが自動で置かれる。1日に何枚でも持てる(ホールごとのシート。マップの上のタブで切り替え)。東京流通センター(GSF/SSF基準・GSF04/SSF11)と、コミケのホールごとの空のCSV(作成用)を同梱。ブロック名の変更、CSVでの書き出し・読み込み(Excelで編集)ができる
- 動線。通路に沿った道のりが短くなるように回る順番を決め(必須を先に)、マップに順番の番号と線を出す。買い終わったサークルは飛ばして「次」を案内。計算は C++(WebAssembly)
- サークルの一括登録(右上の「データ」)。配置番号の一覧を貼り付けるか、カタログのCSVを読み込む
- データの書き出し・読み込み(右上の「データ」)。バックアップと、PCで作ったリストをスマホへ移すのに使う
- データは端末内(IndexedDB)に即保存。サーバーなし・オフラインで動作

## 会場図とピン(マップ)

画面下のタブで「リスト」と「マップ」を切り替えます(今いる方がオレンジの文字になり、上にオレンジの線が付く)。

1. 会場図の画像(PNG・JPEG)を読み込む。日ごとに1枚。とても大きい画像は自動で縮小(長辺4096px)
   - 配置図がPDFしかない場合は、PCでPDFを開いて画像として保存してから読み込む
2. 「ピンを置く」→ 下の一覧でサークルを選び、地図の上をタップするとピンが置かれ、次の未配置のサークルに進む
   - 置いたピンはドラッグで動かせる。「このピンを外す」で外せる
   - 選んだサークルにまだピンが無いときは、他のピンの上をタップしてもそこに置く(混み合った場所でも置ける)
3. 「完了」で通常表示に戻る。ピンをタップするとサークルのカードが出て、そのままチェックできる

- 拡大縮小: 2本指でピンチ、PCはマウスホイール、右下の「＋」「－」、何もない所をダブルタップ。「全体」で全体表示に戻る
- ピンはスペース番号だけを表示(ブロックは地図で分かるので出さない)。色はどのブロックでも同じ赤紫で、会場データのスペースの色とは重ならない。必須は塗りつぶし、できれば白地に赤紫の枠、買い終わりは灰色
- 「未購入のみ」で、買い終わったサークルのピンを隠す
- ピンの位置は画像に対する割合で保存するので、同じ配置図の画像なら差し替えても位置はほぼそのまま
- 書き出し時に「会場図の画像も含める」を選ぶと、画像ごとスマホへ送れる(ファイルは大きくなる)

### 島の編集(ピンの自動配置)

「会場図」→「島を編集する」から。PCでの作業がおすすめです。

1. 「＋島を追加」→ 地図の上をドラッグして、番号のマスを含めて島を1つ囲む
2. ブロック名(例: `3組`、`東ア`、`ア`)と、各辺に印刷されている番号を入れる
   - 上辺・下辺は左から右、左辺・右辺は上から下の順に書く。`23-26`(増える)、`22-15`(減る)、`14,13,36,35`(ばらばら)のどれでも可
   - 番号のある辺だけ入れればよい(壁沿いの1列なら1辺だけ)
3. 入れた番号の位置が地図に表示されるので、印刷とずれていたら島をドラッグで動かす・四隅の丸で大きさを変える
4. 同じ形の島は「複製」→ ドラッグで次の島へ動かす → ブロック名だけ変える(GSFなら3組〜6組は番号が同じ)

- 島が入ると、そのブロックのサークルは配置番号から自動でピンが置かれる(点線のピン)。新しく追加したサークルも自動
- 「03,04」のような2スペースは間に、コミケの「01a」「01b」は01の位置に置く
- 手で置いた・動かしたピンは自動の位置より優先。「ピンを置く」で「自動の位置に戻す」と自動に戻る
- 島の外側の番号の行が列から離れている配置図では、列の端のピンがマス半分ほどずれることがある(隣のマスには行かない程度)
- 島は書き出しファイルに含まれる(会場図の画像を含めなくても、島とピンの位置は移る)

## 会場データ(マス目)

会場の配置をExcelのようなマス目で表したものです。1マスが1スペース番号。
これを使う日は、会場図の画像の代わりにマス目の図を表示し、配置番号からピンの位置を決めます(手で置く必要なし)。

- マップ画面の「会場データ(マス目)を使う」、または「会場図」→「シートを追加・CSVを読み込む」から
  - アプリに入っている会場
    - 東京流通センター(GSF/SSF基準): 基礎になる配置。1組〜13組・ARENA[A]〜[F](924スペース)
    - GSF04/SSF11(東京流通センター): GSF04の配置図に合わせた配置。1組〜11組・ARENA[ア]〜[カ](752スペース)
    - コミックマーケット(東京ビッグサイト): 東1〜3・東7・西・南の4枚をまとめて追加する。CSVはまだ空(1行目だけ)。中身を書いたシートだけ追加され、空のシートは飛ばす
  - この端末で使った会場データ(前回のイベントのものを使い回す)
  - CSVファイル(Excelで作ったもの。UTF-8 / Shift_JIS)
- 確認画面で、ブロックの一覧(色つき)・買い物リストのうち位置が決まる件数・問題点を表示。開催日が複数あれば、使う日を選べる
  - エラー(ピンの位置に影響): ブロック名が決まらないスペース、同じ番号が2か所、ラベルの近くに島が無い、同じ近さに別名のラベル
  - 注意(書き方): 番号の抜け、「#入口」のような # の後ろの文字、! の無い施設名
  - 場所はExcelのセル番地(例: BO3)で表示する。「#会場」の行も数えた、Excelの表示どおりの番地
- 「組」「ARENA」のように名前の共通部分ごとに色分けして表示する(「会場図」→「組ごとに色分けする」で切り替え。端末ごとの設定)
- 島の上下に置いたラベルは、島の中央に表示する(上下の島の両方に効くラベルは、間の通路の真ん中に)
- 「ブロック名を変更」: 今回の配置に合わせてブロック名だけ変える(例: `3組` → `C`)。「置き換える文字」で全ブロックまとめて置き換えもできる。同じ会場データの他の日にも反映できる
- 「CSVで書き出す」→ Excelで直す →「別の会場データにする」→「CSVを選ぶ」で読み込み直す
- 会場データで位置が決まるサークルのピンは動かせない(違うときは配置番号を直す)。会場データに無い番号のサークルだけ「ピンを置く」で手で置ける
- 会場データは書き出しファイルに含まれる(小さいので常に含める)
- 「この日の会場データを外す」で、会場図の画像(あれば)の表示に戻る

### 1日に何枚も使う(ホールごとのシート)

コミケのように会場が広いときは、ホールごとに別のCSV(シート)にします。1枚にまとめると図が大きくなりすぎ、スマホで重くなるため。

- 会場データを追加するたびに、その日のシートが増える。2枚以上になると、マップの上にシートのタブが出る(タブの数字は、そのシートのまだ買っていないサークルの数)
- 同じ名前のシートを読み込むと、中身だけ置き換わる(Excelで直したCSVを読み込み直すとき)
- サークルは、配置番号が見つかったシートに出る(並び順で最初のもの)。どのシートにも無いサークルは「ピンを置く」で、今見ているシートに手で置ける
- 「ホール」(CSVの1行目の3つ目、または確認画面の「ホール」欄)に `東` などを入れると、ホールの違うサークルはそのシートで探さない。ブロック名は大文字・小文字やカタカナ・ひらがなを区別せずに探すため、コミケの `東ア` と `西あ` を取り違えないように必ず入れる
- 「会場図」で、シートの並べ替え(↑↓)・表示の切り替え・外すができる。外したシートに手で置いたピンは、最初のシートに移る
- 動線はシートごと: 「順番を計算」「順番を編集」は表示中のシートのサークルだけを並べる。全体の順番はシートの並び順 → シートの中の順番になる(リストの「回る順」もホールごとにまとまる)。シートを回り終えると、下の欄に次のシートへのボタンが出る

#### コミケのCSVを作る

`public/venues/` の `comiket-east123.csv`(東1〜3ホール)・`comiket-east7.csv`(東7ホール)・`comiket-west.csv`(西ホール)・`comiket-south.csv`(南ホール)は、1行目(`#会場,シート名,ホール`)だけの空のファイルです。

1. Excelで開き、2行目からマス目を書く(書き方は下の表。GSFのCSVが見本になる)
2. そのまま上書き保存(CSV UTF-8 のまま)
3. `npm run build` → アプリの「会場図」→「シートを追加・CSVを読み込む」→「コミックマーケット(東京ビッグサイト)」。書いたシートだけが追加される(ビルドせずに、「CSVを選ぶ」で1枚ずつ読み込んでもよい)

### CSVの書き方

| マスの中身 | 意味 |
|---|---|
| 空欄 | 通路 |
| `#` | 壁・柱(通れない) |
| `■` | 机の内側・サークルの席(島の中のすき間、島先と島の間、壁際のサークルの後ろ。通れない) |
| `23`、`03a` | スペース。ブロックは近くのラベルで決まる |
| `3組23`、`東ア01` | ブロック名つきのスペース(ラベルより優先) |
| `【3組】` | ブロック名のラベル(通路のマスに置く)。触れている島と、同じ列で上下2マス以内の島に効く。近いほうが優先。島の中心より左のラベルは左半分、右のラベルは右半分に効く |
| `!運営本部` | 施設(通れない)。同じ名前の隣り合うマスは1つにまとめて描く |
| `*入口` | 出入口などの目印(通れる)。`#入口` も通れる出入口として読む(注意が出る) |

- 1行目を `#会場,会場名` にすると会場名(シート名)になる。`#会場,東1〜3ホール,東` のように3つ目にホールを書ける
- 島 = スペースと `■` が上下左右につながったまとまり。島と島の間は空欄(通路)を1マス以上あける
- 左右で組名が違う島(GSF04の「11組」と「ARENA[ア]」など)は、島の中心をはさんでラベルを左右に並べる(`【11組】`,`【ARENA[ア]】`)。島が縦に2分割され、左の列が左のラベル、右の列が右のラベルの組になる
- 同梱データの形: 島と島の間 2マス(左右・上下とも)、壁際の道 3マス。島先(端の4席)は島から1マス(■)空ける。島先のある島と無い島(7組・11組)は両端をそろえて同じ長さ(2組・8〜10組の下・ARENA[オ]は例外)。壁際のサークルは後ろに ■ を置いて壁から1マス出っ張らせる
- Excelは `+` `-` `=` `@` で始まるセルを式として扱うため、記号はそれ以外にしてある
- 同梱の会場データ(`trc-gsf.csv` と `gsf04-ssf11.csv`)は `tools/make-trc.py` で生成している(`python tools/make-trc.py`。Pythonが必要。アプリの動作には不要)。通路の幅は先頭の `WALL_AISLE` `GAP` `MID` `END_GAP` で変えられる

## 動線(回る順番)

マップ画面の上の「動線」をオンにします(端末ごとの設定)。

1. 下の「順番を計算」→ スタート地点と「必須を先に回る」を選んで「計算する」
   - スタート地点: 自動(いちばん短くなるサークルから)、または会場データの目印(`*入口` など)
   - まだ買っていないサークルだけを並べる。買い終わったサークルは順番の最初に残る
2. ピンに回る順番の番号(白丸の数字)が付き、まだ買っていないサークルを順に結ぶ線が出る
   - 実線: 次のサークルまで。点線: その先。青い丸: 線の始まり(スタート地点、または最後に買ったサークル)
   - 次のサークルのピンは青い枠で点滅する
3. 下の「次」を押すと、そのサークルのカードが出て地図がそこへ動く。チェックすると線と「次」が先へ進む

- 予定が変わったら: サークルのカードの「ここから順番を計算」で、そのサークルを起点に残りを並べ直す
- 手で直す: 「順番を編集」→ カードの大きな番号を書き換える(その順番へ移る)か、右の ≡ をつかんで上下に動かして保存。動かしたカードは見える位置に出て青く光る
- リスト画面の並び順「回る順」でも同じ順番で見られる(買い終わったものは下へ)
- 距離は「約○マス」(1マス ≒ 1スペースの幅)。会場データの日は通路のマスをたどって測る。
  画像の日は、島の長方形をよけた近道で測る(通路の形までは分からない)
- 順番は各サークルに、スタート地点などの設定は開催日に保存され、書き出しファイルにも含まれる
- 後から追加したサークルは順番の最後に入る(もう一度「順番を計算」すると組み込まれる)

### 計算のしくみ(C++)

`cpp/route.cpp` を WebAssembly(`public/route.wasm`、約7KB)にしたものを使う。読み込めないときは同じ処理の JavaScript 版(`src/route/routeJs.ts`)で計算し、結果は同じになる(70サークルで C++ 約20ms、JavaScript 約60ms)。

1. 通路のマスを8方向に歩く(縦横 10、斜め 14。島の角はすり抜けない)として、ダイクストラ法で目的地どうしの距離を測る
2. 回る順番: 近い順に並べてから、2-opt(一部を逆順にする)と Or-opt(1〜3個を別の場所へ動かす)で、短くならなくなるまで直す。「必須を先に」のときは必須とできればを分けて並べる
3. 決まった順番で、目的地ごとの道のり(通るマス)を求めて線にする

各サークルの「立つ場所」は、スペースのマスのとなりにある通路(会場データの日)か、ピンにいちばん近い通れるマス。
C++ とのやりとりは、JSON と同じ形のオブジェクト(`src/route/types.ts`)を JS 側で数値の配列にして、C++ が用意した固定の大きさの配列に書き込む(C++ 側は標準ライブラリを使わない)。

C++ を直したときだけ、コンパイルし直す:

```sh
npm run build:wasm   # cpp/route.cpp → public/route.wasm(clang か Emscripten の、見つかった方を使う)
npm run build
```

- clang: WSL / Linux なら `sudo apt install clang lld`。Windows なら LLVM を入れる(wasm32 に対応した clang と wasm-ld)
- Emscripten: [emsdk](https://emscripten.org/docs/getting_started/downloads.html) を入れて `emcc` が使える状態にする
- `route.wasm` はリポジトリに入れてあるので、C++ を直さないなら普段の `npm run build` にコンパイラは要らない

## サークル一覧(カタログ)を取り込む

イベント公式サイトの全サークル一覧を取り込んでおくと、名前などで検索してすぐ追加できます。買い物リストとは別に保存されます。

1. PCのブラウザで一覧のページを開き、Ctrl+S(Macは⌘+S)で保存する
2. アプリの「データ」→「サークル一覧」→「一覧を取り込む」で、保存した `.html` を選ぶ
   (ページ上の表を選択してコピーし、貼り付けても可。リンク付きで読み取れる)
3. 列の割り当て(組・番号・サークル名・ペンネーム・作品/キャラ・X・HOME)を確認して保存

取り込んだ後は:

- **一覧から選んで追加**(「データ」画面): 検索して「追加」を押すと、その場で買い物リストに入る。画面は開いたままなので続けて選べる
- **サークル追加画面**: 「一覧から探す」に数文字入れると候補が出て、選ぶと配置とXが入る
- 検索はサークル名・ペンネーム・作品/キャラ・配置・Xアカウントが対象。ひらがな/カタカナ、全角/半角の違いは無視。空白で区切ると「5組 ことね」のように絞り込める
- 一覧が更新されたら取り込み直す(一覧だけ置き換わり、買い物リストはそのまま)。買い物リストのサークルが一覧と配置が違う・一覧に無いときは「データ」画面に表示する(自動では書き換えない)
- 一覧は書き出しファイルにも含まれるので、PCで取り込んでスマホに送れる

取り込んだ一覧は他の人のサークル情報なので、端末の中だけで使い、リポジトリなどには入れないでください。

## サークルをまとめて登録する

右上の「データ」→「サークルの一括登録」から使います。読み取り結果を確認してから追加するので、間違えて登録されることはありません。
同じ日・同じ配置のサークルがすでにあれば「登録済み」として追加しません(何度読み込んでも重複しない)。

**テキストを貼り付け**: 1行に1サークル。配置番号とサークル名の順番は自由です。

```
1日目 東ア-01a サークル名
土曜 西あ12b サークル名
でらせるふ 5組16
たかはる 5組03,04
```

- 読める配置: `東ア-01a` `東ア01ab` `西あ-12b` `南a-03` `5組16` `5組03,04` `A-01` など(全角・半角どちらでも可)
- 日の指定: `1日目` `土曜` `(土)` を行のどこかに書くと、その日に追加。無ければ画面で選んだ日に追加
- X: `@アカウント名` や `https://x.com/...` を行のどこかに書くと、Xの欄に入る
- 曜日は、イベント編集で入れた開催日の日付から自動で対応付けます

**CSVを読み込む**

- コミケWebカタログのお気に入りCSV(チェックリスト形式。1列目が `Circle` の行)は、そのまま読み込めます。曜日・地区・ブロック・番号・サークル名・執筆者名(ペンネーム)・メモを取り込みます
- それ以外のCSVは、どの列が「配置番号」「サークル名」「日」「メモ」かを選んで読み込めます(見出しから自動で推測)
- 文字コードは UTF-8 と Shift_JIS のどちらでも可

頒布物と値段は形式がサークルごとに違うため、一括登録の後に各サークルの編集画面で入力します。

## PCで作ったリストをスマホに移す

1. PCのブラウザでアプリを開き、イベント・サークル・頒布物を登録する
2. 右上の「データ」→「ダウンロード」で `.json` ファイルを保存する
3. ファイルをスマホに送る(Google Drive、iCloud Drive、LINEの自分宛て、メールなど)
4. スマホのアプリで「データ」→「ファイルを選ぶ」→ 内容を確認して「読み込む」

同じイベントがスマホにすでにある場合は、次のどちらかを選べます。

- **置き換える**: スマホ側のそのイベントを、購入チェックも含めてファイルの内容にする(PCで直したリストを反映するとき)
- **別のイベントとして追加**: スマホ側のデータは残し、「(コピー)」を付けて追加する

当日に付けた購入チェックは「置き換える」で消えるため、会場で使い始めた後はPCからの上書きに注意してください。
スマホ側でも「データ」→「共有・保存…」から、ファイルアプリやクラウドに保存できます(機種変更・データ消失への備え)。

## PCでの準備

[Node.js](https://nodejs.org/)(LTS版)を入れてから、このフォルダで次を実行します。

```sh
npm install       # TypeScript を入れる(初回のみ)
npm run build     # dist/ に完成品を作る
npm run serve     # http://localhost:8080 で確認
```

開発中は別のターミナルで `npm run watch` を動かしておくと、`src/` を保存するたびに `dist/js/` が更新されます
(`public/` を変えたときは `npm run build` をもう一度)。

## スマホで使う(GitHub Pages で公開)

PWA(オフライン動作・ホーム画面のアプリ化)には HTTPS での公開が必要です。GitHub Pages なら無料です。

1. GitHub に新しいリポジトリを作り、このフォルダを push する(ブランチ名は `main`)
2. リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にする
3. 以降は `main` に push するたびに `.github/workflows/deploy.yml` が自動でビルド・公開する
4. 公開URL(`https://<ユーザー名>.github.io/<リポジトリ名>/`)をスマホで開き、ホーム画面に追加する
   - iPhone: Safari の共有ボタン →「ホーム画面に追加」
   - Android: Chrome のメニュー →「アプリをインストール」(または「ホーム画面に追加」)

会場に行く前に、Wi-Fi のある場所で一度アプリを開いておけば、当日は圏外でも起動します。
アプリを更新したときも、一度開けば新しい版に切り替わります。

> データはスマホの中だけに保存されます。リポジトリを公開設定にしても、登録したサークル情報が外に出ることはありません。
> 公式カタログの画像などは、アプリに同梱せず(リポジトリに入れず)、端末側で読み込む方針です。
